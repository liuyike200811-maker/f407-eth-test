## 一、板子和电脑之间的物理连接总览

板子上 **3个串口 / 4条数据方向**：

```
┌─────────── COM6 = USB转TTL (USART6, 全双工) ───────────┐
│  PC → 板子 PC7(RX) : 传感器54字节WT姿态帧                │  ← 协议①
│  板子 PC6(TX) → PC : 每周期1字节 '0'/'1' 接收状态         │  ← 协议②
└────────────────────────────────────────────────────────┘
┌─────────── micro-USB = F407原生USB CDC (板子→PC) ───────┐
│  32字节数字孪生二进制帧 + 可读文本 (混在同一流)           │  ← 协议③
└────────────────────────────────────────────────────────┘
┌─────────── CH340 = 板载USB (USART1, 板子→PC) ───────────┐
│  纯可读文本 (与micro-USB里文本同源，但这口不混二进制)     │  ← 备用干净终端
└────────────────────────────────────────────────────────┘
```
所有串口参数统一：**115200, 8, N, 1**。

## 二、协议① COM6写：PC→板子 —— 传感器姿态帧

详见 [02-传感器跟随功能-协议与操作.md](02-传感器跟随功能-协议与操作.md) 第二节，Win端原样透传54字节WT帧即可，什么都不用算。

## 三、协议② COM6读：板子→PC —— 接收状态流（每周期1字节，无帧无校验）

`'1'`(0x31)=本周期至少来了一帧WT数据；`'0'`(0x30)=没来。板子每4ms周期发一个，正常约250字节/秒。

用法：① 数`'1'`的个数 vs "电脑已发送N帧" 比对判丢帧；② 看流在不在动判板子是否卡死/掉电。

```python
ones = com6.read_all().count(b'1')   # 一个统计窗口内的'1'个数
# ones ≈ sent_count → 链路好
```

## 四、协议③ micro-USB读：板子→PC —— 数字孪生帧 + 可读文本（混流，权威32字节格式）

### 数据A：数字孪生二进制帧（定长32字节，自带xor校验）

| 偏移 | 长度 | 字段 | 类型/单位 |
|---|---|---|---|
| 0 | 2 | 帧头 | 固定`0xAA 0x55` |
| 2 | 4 | seq | uint32小端，每帧+1 |
| 6 | 1 | phase | uint8=当前模式：0~4康复/6传感器跟随/99待机 |
| 7 | 12 | pos[3] | float32小端×3，各电缸相对home伸出量，mm |
| 19 | 12 | vel[3] | float32小端×3，各电缸实际速度，RPM |
| 31 | 1 | xor | 偏移2~30这29字节的逐字节异或，校验用 |

> 载荷29字节(偏移2~30)内部布局与旧`webui/server.py`完全一致(`seq@0/phase@4/pos@5/vel@17`，相对载荷)，转发给旧格式消费端时直接发`frame[2:31]`即可。

### 数据B：可读文本

UTF-8编码，按行，`\r\n`结尾，例：`[待机] WKC=9 从站=3 | Modbus 收到帧=X 有效=Y`。不属于数字孪生帧的字节全归文本。

### Win端拆包算法

```
维护字节缓冲buf；每次读到新字节append进buf；循环：
  在buf里找帧头0xAA 0x55
  ├ 没找到: 之前全当文本处理；留末尾可能半个帧头，break
  ├ 找到于位置i:
  │   i之前 → 文本处理(按\r\n切行)
  │   若从i起不足32字节 → 数据没到齐，break等下次
  │   frame = buf[i:i+32]；校验 XOR(frame[2..30])==frame[31]?
  │     是→真帧，解析转发，从buf删到i+32
  │     否→假同步(文本里碰巧出现0xAA55)，frame[0]当文本，从i+1重新找
```

```python
import struct
def check(frame):
    x = 0
    for b in frame[2:31]:
        x ^= b
    return x == frame[31]
seq   = struct.unpack_from('<I',   frame, 2)[0]
phase = frame[6]
pos   = struct.unpack_from('<fff', frame, 7)    # mm ×3
vel   = struct.unpack_from('<fff', frame, 19)   # RPM ×3
```

## 五、备用口 CH340(USART1)：纯净文本终端，micro-USB混了二进制帧别用裸终端看

## 六、Win端要开的COM口一览

| 口 | 方向 | 协议 | 必需? |
|---|---|---|---|
| COM6(USART6)写 | PC→板 | ①54B WT帧透传 | 必需(传感器跟随) |
| COM6(USART6)读 | 板→PC | ②裸'0'/'1'流 | 建议(丢帧比对/存活判断) |
| micro-USB(CDC)读 | 板→PC | ③32B数字孪生帧+文本混流 | 必需(数字孪生转发+面板展示) |
| CH340(USART1)读 | 板→PC | 纯文本 | 可选(备用干净终端) |

⚠ COM口号随插拔/换拓展坞会变，做成下拉选择/自动探测，别写死。
⚠ 去Win端前把最新固件`f407-eth-test.bin`/`.hex`烧进板子。

## 七、FStudio配置要点（HMI读不到反馈时看这）

### 第0步：先盯板子诊断日志（micro-USB口，115200）
每秒一行：`[待机] WKC=9 从站=3 | Modbus 收到帧=X 有效=Y`
- 收到帧X在涨 = 接线/波特率OK
- 有效Y在涨 = 站号/CRC OK，链路通了
- Y涨但HMI没数 = 纯粹寄存器类型/地址填错

### 第一步：通讯参数
Modbus RTU（不是TCP），115200-8-1-无校验，从站站号1。

### 第二步【最容易错】：寄存器类型
数值(设定/反馈)全部是"保持寄存器4x"(读03，写06/16)；按钮(控制)全部是"线圈0x"(读01，写05/0F)。
⚠ 千万别把反馈选成"输入寄存器3x"(功能码04)——板子不支持04，一读就异常，这是"读不到反馈"最常见原因。

### 第三步【第二容易错】：地址编号（原始0基 vs FStudio 1基，差1）

【线圈】模式0~4=原始0~4/1基0x00001~5；归零=5/0x00006；急停=6/0x00007；下电=7/0x00008；故障复位=8/0x00009

【设定4x】α=0/4x00001；β=1/4x00002；频率=2/4x00003(存25=0.25Hz,小数位2)；波幅=3/4x00004；升高=4/4x00005；循环=5/4x00006；升速=6/4x00007

【反馈4x，只读03】运行状态字=16/4x00017；故障从站号=17/4x00018；在线从站数=18/4x00019；WKC=19/4x00020；轴1~3位置=20~22/4x00021~23(**有符号**,小数位1)；心跳=23/4x00024；当前模式=24/4x00025(99=待机)

### 第四步：先只配一个，通了再铺开
先放一个数值显示框绑"心跳"(原始23/1基4x00024，保持寄存器03读)下载测试：心跳在跳=类型+地址+站号全对，照表批量做；不显示则换"原始/1基"两列试。期望值：在线从站数=3，心跳非0变动，状态=1(待机)。

### 第五步：判定口诀
- 收到帧不涨 → 接线/波特率问题，回查MAX3232
- 收到帧涨、有效不涨 → 站号或校验错
- 有效涨、HMI无数 → 寄存器类型或地址错（第二、三步）

## 八、Modbus通讯超时排查（代码层面，HMI配置无误但仍超时时用）

1. **确认Modbus代码是否集成进工程**：`grep -r "modbus_init"/"modbus_poll"/"modbus_usart3_isr" ./`，期望分别出现在 main.c初始化、poll_cmd()内、stm32f4xx_it.c的USART3_IRQHandler()。没有则把代码复制进App/目录并接入构建。
2. **看终端诊断日志**（同上第0步）判断X/Y哪个不涨，定位到接线/波特率 or 站号/CRC。
3. **确认`modbus_write_feedback()`每周期被调用**：`poll_cmd()`末尾必须顺序有 `modbus_poll(); modbus_sync(); modbus_write_feedback();`，缺了反馈寄存器永远是0。
4. **用Modbus Poll/QModMaster单独验证从站**（不接HMI）：RTU/115200-8-N-1/站号1，读保持寄存器(FC03)地址23(心跳)，数字在变=从站正常。
5. **接线备忘（MAX3232）**：HMI DB9 Pin2(RX)←Tout1，Pin3(TX)→Rin1，Pin5(GND)→GND；模块另一侧 T1in←STM32 PB10(USART3_TX)，R1out→PB11(USART3_RX)，VCC→3.3V。TX/RX必须交叉接。

# HMI ↔ STM32 Modbus RTU 寄存器契约（权威 v4，定稿 2026-07-21）

角色：HMI = 主站(Master)，STM32 = 从站(Slave)。
（STM32 对伺服电缸那条 EtherCAT 链路是另一回事，STM32 在那边是主站，与本契约互不影响。）

机器性质：**命令驱动 + 预设动作模式**，不是通用变频器 —— 没有"方向0/1"、没有"目标位置输入"，
每个模式的轨迹是板子内部算好的，HMI 只负责触发模式和调参数。

## 一、串口通讯参数（两边必须完全一致）

| 项 | 值 |
|---|---|
| 波特率 | 115200 |
| 数据位 / 停止位 / 校验位 | 8 / 1 / 无 |
| 从站站号 | 1 |
| 接线 | RS232，HMI COM口 TX/RX 交叉接 STM32 USART3(PB10=TX/PB11=RX)，经 MAX3232 电平转换，GND对GND |

寄存器类型只用两种：**0X 线圈**(位，开关量) / **4X 保持寄存器**(16位数值)。地址基数=0（数组下标=地址号）。

## 二、【控制区】线圈 0X —— HMI写，STM32读，一次性触发（HMI置ON→STM32执行→自动清0）

| 线圈 | 名称 | 动作 |
|---|---|---|
| 0x0000~0x0004 | 模式0~4（波浪/跖背/内外/环形/八字） | `g_run_request = 0~4` |
| 0x0005 | 归零 | `g_do_home = 1` |
| 0x0006 | 急停 | `g_abort = 1`（平滑降速回待机） |
| 0x0007 | 下电退出 | `g_quit = 1`（慎用） |
| 0x0008 | 故障复位 | 清故障显示 |
| 0x0009 | **传感器跟随** | `g_sensor_mode = 1`（v3新增） |

规则：待机时多个模式线圈同时ON，以先读到的为准；运行中只有急停(0x0006)生效。
传感器跟随(0x0009)仅待机受理；与归零(0x0005)同时收到，**归零优先**；跟随中按急停退出（自动归平→下降→回待机）；跟随模式下只用"上升高度/上升速度"，α/β/频率/波幅/循环次数不生效。

## 三、【设定区】保持寄存器 4X —— HMI写，STM32读

| 地址 | 名称 | 单位 | 范围/默认 |
|---|---|---|---|
| 4x0000 | α幅度 | 度 | 0~30，默认15 |
| 4x0001 | β幅度 | 度 | 0~30，默认15 |
| 4x0002 | 频率 | 厘赫×100（25=0.25Hz，小数位设2） | 5~80，默认25 |
| 4x0003 | 波浪幅度 | mm（仅模式0用） | 0~40，默认30 |
| 4x0004 | 上升高度 | mm | 0~80，默认60 |
| 4x0005 | 循环次数 | 次 | 1~99，默认9 |
| 4x0006 | 上升速度 | RPM | 50~200，默认150 |

STM32端对写入值做限幅，越界自动截断。

## 四、【反馈区】保持寄存器 4X —— STM32写，HMI只读 ⚠地址以此为准，不是旧文档写的4x0010起

| 地址 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 4x0016 | 运行状态字 | 无符号 | 0启动中 1待机 2运行中 3归零中 4故障 5已下电 **6体感控制中**(v4) |
| 4x0017 | 故障从站号 | 无符号 | 0无故障，1/2/3=对应从站报警 |
| 4x0018 | 在线从站数 | 无符号 | 正常=3 |
| 4x0019 | WKC | 无符号 | 正常≈从站数×3=9 |
| 4x0020 | 轴1位置 | **有符号** | mm×10（存425=42.5mm），相对归零点 |
| 4x0021 | 轴2位置 | 有符号 | 同上 |
| 4x0022 | 轴3位置 | 有符号 | 同上 |
| 4x0023 | 心跳计数 | 无符号 | 每拍+1溢出归零，判通讯是否活着 |
| 4x0024 | 当前运行模式 | 无符号 | 0~4=对应模式，**6=传感器跟随中**(v3)，99=待机 |

⚠ **历史勘误**：本节地址此前文档误写为连续编号 4x0010~4x0018，但 STM32 代码里 `modbus_hreg[]` 反馈区实际下标是 **16~24**（见 `App/ecat_motion.c` 的 `modbus_write_feedback()`）。FStudio 反馈页已按 16~24 配置并验证通过，v4 起统一改正文档，旧编号作废。

**4x0016 与 4x0024 的分工**：4x0016 是宏观状态机（运行中/体感控制中是并列的两种独立状态）；4x0024 是具体在跑哪个动作（体感模式下固定写6）。**两者必须同一帧内同步置位/复位**，不能只改一个，否则HMI上"状态"和"当前模式"两个指示灯会显示矛盾。

HMI显示设置：4x0020~4x0022选"有符号数"+小数位1；心跳做"通讯正常"指示灯；状态字/当前模式各自做文字状态灯。

## 五、STM32端实现要点

- USART3(PB10/PB11) 115200-8-N-1，挂 Modbus RTU 从站（功能码只需01/02/03/05/06/0F/10）
- 两个数组：`uint16_t holdingRegs[25]; uint8_t coils[16];`，地址=下标（基数0）
- 收发解析必须挂进 `poll_cmd()`，与现有 USART1/USB 并列，保证运动中也能实时响应急停
- 写请求→翻译成 `g_run_request/g_abort/g_do_home/g_quit`，翻译后清线圈位；设定区同步进 `g_aa_deg..g_rise_rpm`（带限幅）
- 每周期把反馈写进 `holdingRegs[16..24]`
- 建议先用 Modbus Poll / QModMaster 单测从站，再接HMI联调

## 六、HMI(FStudio)端配置要点

- 通讯设置：COM口、制造商=Modbus兼容设备、类型=ModbusRTU、参数按第一节、地址基数=0
- 控制区线圈0x0000~0x0009→10个按钮；设定区4x0000~4x0006→7个数值框（频率2位小数）；反馈区4x0016~4x0024→状态灯/文字+三轴位置(有符号1位小数)+心跳灯+当前模式显示
- 传感器跟随(0x0009)按钮另需USB转TTL把传感器数据接到板子USART6/PC7，链路见 [02-传感器跟随功能-协议与操作.md](02-传感器跟随功能-协议与操作.md)
- 离线模拟后再实机联调，具体排错步骤见 [03-Win端数据转发与HMI排错.md](03-Win端数据转发与HMI排错.md)
